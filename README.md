## ขั้นตอนติดตั้ง
1. เปิด `js/config.js` ตรวจสอบ Supabase URL และ publishable/anon key ให้เป็นของโปรเจกต์คุณ
2. ตรวจว่าได้สร้าง `person_claim_codes` และ `claim_existing_person(text)` ตาม SQL ที่ทำไว้ก่อนหน้าแล้ว
3. รัน `sql/02-claim-function-patch.sql` ใน Supabase SQL Editor เพื่อสร้างฟังก์ชัน `claim_existing_person_by_name(text,text)` ซึ่งหน้า Register เรียกใช้
4. รัน `sql/04-relation-names.sql` (ต้องรันก่อน deploy หน้าเว็บเวอร์ชันนี้ เพราะหน้าเว็บบันทึกคอลัมน์ `father_name`, `mother_name`, `spouse_name`)
5. รัน `sql/05-address-fields.sql` (ต้องรันก่อน deploy หน้าเว็บเวอร์ชันนี้)
6. รัน `sql/06-storage-avatar-policies.sql` (ถ้าไม่รัน การแนบรูปจะขึ้น row-level security error)
7. รัน `sql/07-birthdates-children.sql` (ต้องรันก่อน deploy หน้าเว็บเวอร์ชันนี้ ไม่เช่นนั้นเข้าสู่ระบบและลงทะเบียนไม่ได้)
8. รัน `sql/08-nickname.sql` (ต้องรันก่อน deploy หน้าเว็บเวอร์ชันนี้ เพราะหน้าเว็บบันทึกและอ่านคอลัมน์ `nickname`)
9. รัน `sql/09-child-links.sql` (หลัง 08; ถ้าไม่รัน ชื่อบุตร/ธิดาจะกดดูข้อมูลไม่ได้)
10. รัน `sql/10-family-tree.sql` (หลัง 09; **ต้องรันก่อนใช้หน้าเว็บเวอร์ชันนี้** ไม่เช่นนั้นลงทะเบียน/แก้ไขโปรไฟล์จะ error เพราะยังไม่มีคอลัมน์ใหม่)
11. รัน `sql/11-family-circles.sql` (หลัง 10; เปลี่ยนสิทธิ์อ่านตาราง person จาก "ทุกคน" เป็น "เฉพาะวงครอบครัว" ต้องรันก่อน deploy เว็บเวอร์ชันนี้ เพราะหน้าลงทะเบียนเรียกฟังก์ชัน `person_name_taken`)
12. รัน `sql/12-line-contact.sql` (หลัง 11; ต้องรันก่อน deploy เว็บเวอร์ชันนี้ ไม่เช่นนั้นการบันทึกโปรไฟล์จะ error)
13. รัน `sql/13-tree-age.sql` (หลัง 11; ไม่รันก็ใช้งานได้ แต่การเรียงตามอายุจะไม่ทำงาน)
14. รัน `sql/14-deceased.sql` (หลัง 13; ต้องรันก่อนบันทึกโปรไฟล์เวอร์ชันนี้ เพราะมีคอลัมน์ `deceased` ใหม่)
15. รัน `sql/15-optional-phone.sql` (หลัง 14; ต้องรันก่อนใช้เวอร์ชันนี้ ไม่เช่นนั้นลงทะเบียนโดยไม่กรอกเบอร์จะ error)
16. รัน `sql/16-clans.sql` (หลัง 15; เปลี่ยนสิทธิ์อ่านจาก "นามสกุลเดียวกัน" เป็น "ตระกูล" และจัดข้อมูลเดิมเข้าตระกูลตามนามสกุลครั้งเดียว) จากนั้นรันคำสั่งตั้งผู้ดูแลสูงสุดคนแรกท้ายไฟล์ (ยังไม่มีหน้าเว็บจัดการ: ใช้ผ่าน SQL/RPC ไปก่อน)
17. รัน `sql/17-clan-tree.sql` (หลัง 16; ต้องรันก่อน deploy เว็บเวอร์ชันนี้ เพราะหน้าต้นไม้เรียก `tree_clans` และ `family_tree_data(p_clan_id)` และฟังก์ชันเดิมที่ไม่มีพารามิเตอร์ถูกลบ)
18. รัน `sql/18-admin-edit-linked.sql` (หลัง 17; ต้องรันก่อน deploy เว็บเวอร์ชันนี้ เพราะหน้า admin เรียก `clan_get_person`)
10. ตรวจว่า RLS บน `person` มี SELECT สำหรับ authenticated และ INSERT/UPDATE/DELETE เฉพาะ `auth_user_id = auth.uid()` เท่านั้น และไม่มี policy anon แบบเปิดกว้างหลงเหลือ
11. ใน Supabase Auth หากใช้ username ที่แปลงเป็นอีเมลภายใน ให้ปิด Confirm email สำหรับเดโมนี้ มิฉะนั้นต้องทำ flow ยืนยันบัญชีให้ครบก่อนเชื่อมข้อมูล
12. ตั้ง Storage bucket `family-avatars` เป็น public เพื่อให้ `getPublicUrl()` ใช้ได้ หรือปรับโค้ดเป็น signed URLs และกำหนด Storage policies ให้ปลอดภัย
13. เปิดผ่าน VS Code Live Server หรือเว็บเซิร์ฟเวอร์ ไม่แนะนำ `file://`

## การเชื่อมบุคคลเดิม
ผู้ดูแลสร้าง Claim Code สำหรับ `person.id` ที่ยืนยันตัวบุคคลแล้ว และส่งให้เจ้าตัวผ่านช่องทางที่เชื่อถือได้ รหัสมีอายุจำกัดและใช้ได้ครั้งเดียว อย่าออก Claim Code โดยอาศัยชื่ออย่างเดียว

## ข้อจำกัด/ความปลอดภัย
- Supabase Auth ไม่มี username แบบกำหนดเองโดยตรง โค้ดสร้างอีเมลภายในจาก hash ของ `ชื่อจริง|เบอร์โทร` (`accountEmail()` ใน `js/shared/common.js`) จึงมีชื่อจริงซ้ำกันได้ถ้าเบอร์ต่างกัน
- เบอร์โทรถูก normalize เป็นตัวเลขล้วน (`081-234-5678`, `+66812345678` → `0812345678`) ทั้งตอนสมัครและล็อกอิน
- บัญชีที่สมัครด้วยระบบเดิม (Username = ชื่อ-นามสกุล) ยังล็อกอินได้โดยพิมพ์ชื่อ-นามสกุลเต็มในช่อง Username
- `supabase/functions/username-auth` ไม่ได้ถูกใช้โดยหน้าเว็บ และยังไม่ได้ deploy
- รหัสผ่าน = วันเดือนปีเกิด `DDMMYYYY` โดยปีเป็น **พ.ศ.** (เกิด 22 มี.ค. 2547 → `22032547`) ตามความต้องการ แต่วันเกิดเป็นข้อมูลที่คนอื่นรู้หรือเดาได้ง่าย ไม่เหมาะกับระบบใช้งานจริง ควรให้ตั้งรหัสผ่านเองหรือบังคับเปลี่ยนเมื่อเข้าสู่ระบบครั้งแรก
- รหัสผ่านส่งให้ Supabase Auth (`signUp` / `updateUser`) ซึ่งเก็บแบบ hash เท่านั้น ไม่มีคอลัมน์รหัสผ่านในตาราง และไม่แสดงรหัสผ่านบนหน้าเว็บ
- แก้วันเกิดในหน้าโปรไฟล์ไม่เปลี่ยนรหัสผ่าน ต้องติ๊ก "ตั้งรหัสผ่านใหม่เป็นวันเกิดนี้" และยืนยันก่อน
- บัญชีที่สมัครก่อนเปลี่ยนระบบยังใช้เบอร์โทรศัพท์เป็นรหัสผ่านได้ จนกว่าจะตั้งรหัสผ่านใหม่เป็นวันเกิดในหน้าโปรไฟล์
- `login_emails()` เรียกได้โดยไม่ต้องล็อกอิน จึงบอกได้ว่ามีบัญชีชื่อจริงนี้หรือไม่ (คืนเฉพาะอีเมลภายในที่เป็น hash)
- หน้าโปรไฟล์แสดงเฉพาะอายุ (คำนวณจากวันที่ปัจจุบันเวลาไทย) ถ้าไม่มีวันเกิดแสดง "ไม่ระบุ"; ปิดสวิตช์วันเกิดจะไม่ลบวันเกิดที่บันทึกไว้ เว้นแต่ผู้ใช้กดยืนยันให้ลบ
- ถ้าการสมัคร Auth สำเร็จแล้วแต่ขั้นตอนเชื่อมข้อมูลล้มเหลว บัญชี Auth อาจยังคงอยู่; ให้แก้สาเหตุแล้วเข้าสู่ระบบด้วยบัญชีนั้น ไม่ควรสมัครซ้ำ
- ลบแถว `person` ไม่ได้ลบบัญชี Auth อัตโนมัติ
- ห้ามนำ Supabase service_role key มาใส่ในไฟล์หน้าเว็บ
